# 纸坊 · 客户纸样打样与确认台

面向纸坊的客户纸样打样、检测、复核与确认台账。零依赖，仅用 Node.js 内置模块（建议 Node ≥ 18）。

## 运行

```bash
npm start
```

访问 `http://localhost:3039`。数据保存在 `data/paper-proofing.json`（JSON 文件，原子落盘）。
可用 `PORT` / `DB_PATH` 环境变量覆盖端口与数据文件位置。

## 测试

```bash
npm test
```

使用标准入口 `node --test`（无位置参数，自动发现 `test/` 下用例），在 Node 20 与 Node 22 下均完整执行。
共 21 个用例（`test/flow.test.js`、`test/rules.test.js`、`test/http.test.js`、`test/entrypoints.test.js`）：
完整走通送样→检测→复核→驳回→修订→复核→确认锁定→新版本，以及越权、并发生成、
失败回滚、跨重启持久化、旧数据兼容迁移、筛选与统计一致性；另含交付入口回归——
在**含空格与中文的项目路径**下真实派生 `npm start`（持续监听、页面可访问）与 `npm test`（全部业务用例执行）。

## 业务规则

### 登记
- 打样单登记：客户、**用途**、长×宽、厚度、纹理、色差 ΔE 上限，可逐项设置公差（默认 长宽 ±2mm、厚度 ±5μm、ΔE 1.5）。
- 每次送检的检测必须填写**完整检测值**（长、宽、厚度、纹理、色差），缺项拒绝。
- 同一打样单**只能保留一个待检试样**；重复送检、越序操作一律拒绝。
- 检测值超出登记公差、纹理与登记不符，提交拒绝。
- 检测现场判定超差可「判废」：必须附完整检测值且至少一项确实超差。

### 复核与确认
- **检测人不能复核自己的试样**（即使本人兼有复核角色）。
- 复核驳回 / 检测判废 / 客户驳回后，本轮终止；**必须新建修订轮**，旧轮只读保留。
- 客户确认后**锁定版本**；锁定版本上的直接修改一律拒绝，需要调整时**生成新版本**，旧版本归档只读。
- 所有写操作带乐观版本号，**过期写入返回 409 拒绝**。

### 状态机

```
待送样 ──送检──▶ 待检测 ──登记完整合格检测值──▶ 待复核 ──通过──▶ 待确认 ──客户确认──▶ 已确认（锁定）
                   │                              │                  │
                   └──判废──┐                     └──驳回──┐         └──客户驳回──┐
                            ▼                              ▼                      ▼
                         已驳回 ◀──────────────────────────┴──────────────────────┘
                            │
                            └──新建修订轮──▶ 新轮（待送样），旧轮只读
```

### 筛选与统计
按客户、用途、版本（当前版本/所有版本/指定版本）、偏差分级（≤半公差 / 半~全公差 / 超差 / 无检测值）、
确认状态筛选；统计卡片与明细列表使用同一数据源、同一过滤管线，数字恒等。
